# ADR-001: Agent Framework and MCP Integration

**Status:** Proposed — POC

## Context

The POC accepts a shopping request through stdin or a text file and uses Zepto's MCP server to find products and add them to the cart.

The primary goal is to experiment with LLM-driven tool interaction and sequential actions, not structured output.

## Initial Approach

- **Agent framework:** LangChain agent runtime.
- **LLM:** Ollama running locally.
- **MCP integration:** LangChain's MCP support.
- **MCP transport:** Streamable HTTP, connecting directly to Zepto's remote MCP server.
- **Input:** Stdin or a text file.

LangChain manages the agent loop. The LLM chooses tools and supplies arguments based on the user's request and previous tool results.

## Safety Constraints

- Expose only explicitly allowlisted MCP tools to the agent.
- Allow product search, product details, cart inspection, and cart modification.
- Exclude checkout, payment, and order-placement operations.
- Do not introduce Telegram or a task queue in this POC.

## Alternatives to Revisit

- Use `mcp-remote` over stdio if direct Streamable HTTP authentication proves incompatible.
- Evaluate another agent framework if LangChain's local-model tool calling is inadequate.

## Experiments

1. Connect to Zepto using LangChain's direct Streamable HTTP integration.
2. Validate authentication and MCP tool discovery.
3. Test tool calling with the locally served Ollama model.
4. Test sequential product search and cart modification.
5. Verify that restricted tools are unavailable to the agent.

## Decision Review

This is an experimental starting point, not a final architecture commitment. Update the document based on observed results.
